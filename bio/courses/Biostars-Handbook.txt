### 01: Intro
    - $MY_VIDEOS/bio/Biostars/01-Getting-Started.mp4
    - No focus on algorithms and implementation details eg.
        - Dynamic Algorithms, 
        - Burrows-Wheeler, 
        - DeBruijn Graphs
    - Its important stuff but most people don't need it
    - We concentrate on information processing - reimagining
      bioinformatics from a data oriented perspective. 
        - Data is king! 
        - Tools just transform data, and data may (or may not)
          give answers
    - We have more data than we know how to extract yet!  You
      could discover something!
    - Bioinformatics requires many relatively simple decisions.
    - We will concentrate on COMMAND LINE tools.
    - R (Bioconductor): Best suited for later stage analysis.
    - Bioinformatics is:
        - IT:
            - data storage, transfer
        - CS:
            - algorithms advanced data structures
        - STATS:
            - traditional stats not suited to modelling
              systematic errors over large number of
              observations.
            - Also: different stats process for biological
              systems compared to Higgs boson / LHC discovery.
              (because every electron is the same)
            - Biological systems dont follow mathematical
              principles. Exceptions are far more frequent. They
              all have systematic behaviours, and some systematic
              behaviours will _ADD UP_ and not cancel out over
              a large number of observations.
            - A fundamental requirement of statistics is if you
              make a sufficient number of observations, you make
              errors both ways and eventually they cancel out.
            - Maybe the observation is less certain but you know
              approximately what the median is.
            - but if you systematically overcount in one way,
              statistics and doing a large number of observations
              takes you the wrong way
            - So stats done in a bioinformatics protocol is
              a separate field of stats
        - Life Sciences:
            - biological hypothesis testing, interpretation
            - we want insight into bio processes

    - Try to understand what we're doing!
    - View 1:
        - Run "bowtie" aligner, then run "cutdiff" software
    - View 2:
        - Create a spliced alignment file, quantify the
          abundances by intersecting the alignments with the
          genomic intervials. Then apply a statistical test to
          select differentially expressed entries.

### 07 Sequencing Instruments
    - $MY_VIDEOS/bio/Biostars/07-Sequencing-Instruments.mp4
    - short read sequencing
    - 1st: fragmentation   (variable size)
    - but there could be a population of cells in the original
      soup
    - machine can read only 200 - 300 base pairs  (so if fragment
      longer than that?)
    - double stranded fragments broken into single strands
    - forward strand, reverse strand
    - 5' end is start: and "read" shown as an arrow
    - stochastic process, not guaranteed all fragments will be
      read!
    - for "i" sequencer, all reads will be the same length.
    - read length could be same length as fragment
    - single end sequencing?
    - or middle of fragment read twice, once from each side
    - can delete away the reverse orientation fragment
    - sense and anti-sense (2nd read is usually anti-sense)
    - the 5' ends in each read are really important... you know
      that bit is right, although you dont know how far along the
      fragment the read actually went
    - COVERAGE:
        - how many reads cover a particular bit of a fragement?
          (certain location of the fragement)
        - coverage: some of read lengths / genome (length?)
        - raise 50x coverage?  do more reads, or increase read
          length
        - probability of base not being covered: e^(-coverage)
    - "fragmentation is never really random"  ???

### 12a Sequence Alignments
    - https://www.biostarhandbook.com/introduction-to-alignments.html
    - $MY_VIDEOS/bio/Biostars/12a-Sequence-Alignments.mp4
    - goal: generate meaningful alignments
    - each proposed alignment could be an explanation different
      biological phenomena:
        - eg the "TA" was deleted from inside the sequence
          "GATTACA"
    - an aligner gives us "graded" alignments depending how we
      rate (or "scorel") different freatures: eg missing base
      missing from the end, or missing from the middle
    - alignment score ("most likely")
    - `global-align.sh  GATTACA GATCA`
    - `local-align.sh`
    - Another use case:
        - I have a query sequence "GATTACA" and I want to see
          where in the organism it comes from
        - it may be found in several different locations in the
          organisms genome; I need to find the "origin" of the
          sample in the reference genome
    - What influences the final result:
        - the alignment algorithm used
        - the scoring (numerical value assigned to different
          arrangements)
        - The aligner will give you the arrangement that gives
          the max score / value
        - "penalty"
    - The more different the sample sequence is, the more
      sensitive it becomes to alignment choices. ie if you have
      an EXACT match then the aligner will return same result
      each time, it only gets messy when you dont have an exact
      match
    - assume "top" alignment is the reference. So you report "3
      deletions" and an "insertion" relative to the reference.
    - How does alignment scoring work?  A scoring MATRIX is
      built...
        - each matrix represents an _evolutionary distance_
    - also: aligners dont really penalise gaps at the end
    - Useful paper for proteins: "Selecting the Right Similarity
      Scoring matrix"
    - CIGAR string: another way of representing an alignment
      match: 4M = 4 matches  . `7M3D7M...`
        - reports a lot of info in one shot
        - also "extended" CIGAR string

### 14 Short Read Aligners
    - https://www.biostarhandbook.com/short-read-aligners.html
    - $MY_VIDEOS/bio/Biostars/14-Short-Read-Aligners.mp4
    - Sequencing used be a long process... scientist would go out
      and get a fairly long sequence: 1000 base pairs
        - blast paradigm: I have one fairly long sequence and
          I want to see what its similar to
    - Around 2005, the arrival of the high-throughput short-read
      technology changed this picture
    - could CREATE 100s of millions of reads in a single
      experimental run: but only 50 base pairs per READ
    - then you have almost the reverse of BLAST: we've many many
      sequences from ONE genome and want to look them up onto the
      one where they go...
    - each read is like a "measurement". and we ignore reads that
      don't align.
    - amazing performance: well optimised aligner will match
      10,000 sequences per second against 3 billion bases of
      human genome
    - difference between "mapping" and "alignment"?
        - 90% of the time it means the same even though theres
          a technical difference
        - MAPPING: 
            - takes a sequence and knows it covers the genome
              from eg position 100 to 200. "I know which region
              it comes from"
        - ALIGNMENT: 
            - I believe this sequence has eg 2 insertions and
              1 deletion when we place it next to a genome.
        - you could have a right "alignment" and a wrong
          "mapping".
        - MAPPING: location in genome
        - ALIGNMENT: proper arragnement of bases in that region
        - we want the aligner to do both (but its not guaranteed)
    - errors: the data can have errors, how the aligner handles
      this is important.
    - he did a demo with the "bwa" aligner. Only need "mem" and
      "index". The other commandline paraemteres are historical.
    - All SAM files should be sorted.  They are uncompressed
      binary files.
