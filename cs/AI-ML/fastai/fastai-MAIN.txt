### Use learn.model? (for multi-target)
    - in the context of a custom prediction function for
      a multi-target model, you should directly use
      `learn.model(processed_img)` instead of
      `learn.predict(processed_img)`. Here's why:

    - Direct Model Call: learn.model(processed_img) directly
      invokes the underlying PyTorch model with the processed
      image. This is necessary when dealing with custom model
      structures, like multi-target models, where you want to
      access the raw outputs directly.

    - learn.predict Limitation: `learn.predict` is a high-level
      function designed for standard single-target prediction
      scenarios. It handles preprocessing, prediction, and
      postprocessing (decoding) steps automatically, but it
      expects the model and data to follow the standard
      single-target format. 
        - In the case of _multi-target models_, `learn.predict`
          might not correctly interpret and decode the model's
          outputs, leading to errors or incorrect predictions.

    - By directly using learn.model, you bypass these limitations
      and get the raw output from your model, which you can then
      decode manually as per your model's specific structure.
      This approach gives you more control over the prediction
      process, which is essential for non-standard models like
      yours.

        - img = PILImage.create(image_path)
        - # Process the image (the same way your DataLoaders do)
        - processed_img = learn.dls.test_dl([img]).one_batch()[0]
        - # Get raw predictions
        - raw_preds = learn.model(processed_img)

### Models: Load/Save (1)

          learner.load method:
            - learner.load('ultrasound_classifier')

    - `learner.export` To export entire model including
      architecture, optimizer, and other associated information
      for DEPLOYMENT, use the `learner.export`:
        - learner.export('path_to_save/exported_classifier.pkl')
            - Note:  pickle format (pkl).
        - To use it for inference on new data,
          load it using:
            - loaded_learner = load_learner('path/exported_classifier.pkl')

### fit_one_cycle versus fine_tune
    - In the FastAI library, `learn.fit_one_cycle(...)` and
      `learn.fine_tune(...)` are two different approaches for
      training a model.

    1. **`learn.fit_one_cycle(...)`**:
    - This implements the "1cycle" policy, a technique proposed
      by Leslie Smith that involves varying the learning rate and
      momentum in a specific way during training.
    - It starts with a lower learning rate, gradually increases
      to a maximum, and then decreases again. This helps in
      faster convergence and potentially better training
      outcomes.
    - It's effective for training from scratch or when you're NOT
      starting with a pre-trained model.

    2. **`learn.fine_tune(...)`**:
    - This method is specifically designed for fine-tuning
      pre-trained models.
    - It's a two-step process:
        - First, it freezes all model layers model except the
          last layer(s) and trains for a specified number of
          epochs. This helps in adapting the model's final layers
          to the new data.
        - Then, it unfreezes the entire model and continues
          training (usually with a lower learning rate) to
          fine-tune the weights throughout the model.
            - This step adjusts the pre-trained weights to better
              suit the specific task at hand.
    - It's commonly used in _transfer learning_ scenarios, where
      you start with a model trained on a different but related
      task.

    In summary:
    - Use `fit_one_cycle` for general training or when NOT using
      a pre-trained model. It's about efficient training with
      a dynamic learning rate.
    - Use `fine_tune` for transfer learning scenarios, to adapt
      a pre-trained model to your specific task with a careful,
      two-step process.

### Important Gradient code (chain rule)
    - lr = 1e-5
    - params.data -= lr * params.grad.data
    - params.grad = None

      `loss`.

          turn took `preds` as an input.
        - `preds` was calculated using `f` taking as an input
          `params`,
        - `params` was the object on which we originally called
          `required_grads_`... which is the original call that
          now allows us to call `backward` on `loss`.

    - This chain of function calls represents the mathematical
      composition of functions, which enables PyTorch to use the
      chain rule under the hood to calculate these gradients.

### Datasets / DataLoaders 1
    - Dataset and DataLoader are core PyTorch concepts.

    - A `Dataset` is just an object that returns:
        - a LENGTH (the number examples in your dataset) and
        - the OBJECT at a given index (between 0 and length).
        - That object can be anything.
            - Usually it’s an image and its label, but if
              examples in your dataset consist of 3 images and
              7 labels, your Dataset’s __getitem__ would return
              a tuple of those 10 things.
            - Check this?

    - A `DataLoader` is a built-in PyTorch object (although you
      can create your own) that grabs a batch of examples from
      a Dataset and puts them into a tensor.
        - It does this as efficiently as possible, using
          _multiple worker processes_ etc, so that multiple
          batches can be loaded in parallel.

    - The `DataLoader` uses a sampler to decide which examples to
      pick for each batch.
        - A DataLoader used for training
            - typically uses a random sampler,
        - while a DataLoader for evaluation
            - will use a sequential sampler.

    - The DataLoader also uses a `collate` function to convert
      the tuple of data returned by your Dataset into a PyTorch
      tensor.
        - Usually you can use the default collate function, but
          let’s say your Dataset returns 3 images and 7 labels
          for each example, you might need a custom collate
          function to turn this into a tensor.

    - You just have to provide an implementation for the Dataset.
      The DataLoader, sampler, and collate functions are built
      into PyTorch already (unless you want to use your own, in
      which case you can override them).

    - The `DataBlock` is a fastai-specific thing that makes it
      easy to create all the datasets and loaders that you need.
      It’s provided just for convenience and saves you writing
      a bunch of this code yourself.

### dataloader fact
    - I thought if `batch_size=5` or `10`, it would just create
      loads and loads of batches...
    - I thought it was batches _with replacement_
    - but it only creates as many batches as actual items exist
      in the dataloader
    - if `n=15`, and `batch_size=10`,
        - then 2 batches created:
        - batch 1: `[a, a, a, a, a, a, a, a, a, a]`,
        - batch 2: `[a, a, a, a, a]`
        - to use up all 15 items
    - Python example:
        - coll = range(15)
        - dl = DataLoader(coll, batch_size=10, shuffle=True)

### Jargon/Glossary/Terminology (from fastai)
    - Label                 The data we’re trying to predict, such as “dog” or “cat”
    - Architecture          The template of the model that we’re using to fit; The mathematical _function_ we’re passing input data and parameters to
    - Model                 The combination of the architecture ALONG WITH a specific set of parameters
    - Parameters            (Weights? + bias?) The model values that change what task it can do (and are updated through model training)
    - Fit                   Update the model parameters so the model predictions from input data, match the target labels
    - Train                 Synonym for fit
    - Pretrained            A model that has already been trained, generally using a large dataset, and will be fine-tuned model
    - Fine-tune             Update a pretrained model for a different task
    - Epoch                 One complete pass through the input data
    - Loss                  Measure of how good the model is, chosen to drive training via SGD
    - Metric                Measurement of how good the model is using the validation set, chosen for _human consumption_
    - Validation set        Data held out from training, used only for measuring how good the model is
    - Training set          The data used for fitting the model; does not include any data from the validation set
    - Overfitting           Training a model so it remembers specific features of the input data, rather than generalizing well to unseen data
    - CNN                   Convolutional neural network; a type of neural network that works particularly well for computer vision tasks

    - SGD CONCEPTS:
    - -------------
    - ReLU                  Function returning `0` for negative numbers and doesn't change positive numbers.
    - Mini-batch            A small group of inputs & labels gathered together into two arrays. A gradient descent step is updated on this batch (rather than a whole epoch).
    - Forward pass          Applying the model to some input and computing the predictions.
    - Loss                  A value representing how well (or badly) our model is doing.
    - Gradient              The derivative OF THE LOSS with respect to some parameter of the model.
    - Backward pass         Computing the gradients of the loss with respect to all model parameters.
    - Gradient descent      Take step in OPPOSITE directions to the (positive?) gradients to make model parameters a bit better.
    - Learning rate         The _STEP size_ when applying SGD to update the model parameters.

    - NUMBERS
    - -------
    - Activations           Numbers that are calculated (both by linear & nonlinear layers)
    - Parameters            Numbers that are randomly initialized and optimized "weights" (ie, numbers that define the model)
