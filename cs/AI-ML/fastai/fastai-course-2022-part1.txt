    - The DL field has settled down, and a limited number of
      useful models identified now.
    - You'll spend more time with `datablocks` and `dataloaders`
      than tweaking model architectures.
    - transforms:
        - all items you train on should be the same size
    - dataloaders feed a batch of images to the GPU at once... so
      you are utilising parallel processing
    - a MODEL:
        - is the input DATA (in a dataloader) + the NN
          architecture (e.g. resnet)
    - `learn.predict` returns 3 things:
        - prediction as string
        - prediction as integer
        - probability of bird/non-bird (for example)
    - Tabular data: not really going to use `fine_tune` because
      that's for pretrained models only. And for tabular
      (financial) data we don't usually have pre-trained models
    - `dls.show_batch()`
        - uses "type dispatch" to show a resonable representation
          of the data, not matter what type it is: image, text,
          numerical etc
    - y_range(0.5, 5,5)
        - if the learner is not predicting a category, but
          predicting a REAL NUMBER
        - also: loosen the range a little; we're interested in
          a range of 1 to 5, but go a bit above and below
    - `fine_tune(10)`
        - confusing: even if it's not a pre-trained model with
          existing weights, we can just do `fine_tune` anyway and
          it'll do normal training
            - $MY_IMAGES/cs/AI-ML/fastai/fine-tune-used-as-trainer.jpg
    - negative numbers-
        - when adding up and multiplying the weights Jeremy
          says... "... takes all the negative numbers and puts
          them to zero"

    - pandas tricks:
        - `fillna` with the mode,
        - df.describe(include=[np.number])
    - long-tailed distributions
        - not good for linear models
        - trick: use the log to get rid of the long tail
        - log makes big numbers less big, and doesn't really
          change small numbers at all
        - note: log of zero is `NaN`, so do np.log(df.fare `+ 1`)
    - wow: there's some categorical variables (sex, passenger
      class, emarked) and you can't multiply them by a numerical
      coefficient... so do
        - df=pd.get_dummies(df, columns=[sex, etc etc])
        - creates new columns: sex_male, sex_female, pclass_1,
          pclass_2 etc etc
        - $MY_IMAGES/cs/pandas-get-dummies.jpg
        - $MY_IMAGES/cs/pandas-get-dummies-2.jpg
        - later: when talking about random forest, Jermey defines
          'sex' as a categorical variable
            - df['Sex'] = pd.Categorical(df.Sex)
            - and that converted Female into 0, Male into 1
            - (so we don't have to do this dummy variable stuff?)
    - Random forests:
        - trying to find the best binary split threshold point
          for `age`
        - he gets all unique `age` values and passes them to his
          "score function" in turn
        - the score function gets the `std` of the group * number
          of items in the group
        - basically we want items in the group to be as low as
          possible (hence `std`)
