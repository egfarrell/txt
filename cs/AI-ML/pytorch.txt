### 3 ways making "nn.Sequential" network
    - method 1 "class"
        - in_features  = image.numel()
        - out_features = math.floor(in_features / 2)
        - out_classes  = len(train_set.classes)

        - network1 = nn.Sequential(
        -     nn.Flatten(start_dim=1) # dim=1: we want to flatten individual image, not whole BATCH
        -     nn.Linear(in_features, out_features),
        -     nn.Linear(out_features, out_classes),
        -     )

    - method 2 "dict"
        - layers = OrderedDict([
        -     ('flat', nn.Flatten(start_dim=1))
        -     ,('hidden', nn.Linear(in_features, out_features))
        -     ,('output', nn.Linear(out_features, out_classes))
        - ])
        - network2 = nn.Sequential(layers)

    - method 3 "add_module"
        - network3 = nn.Sequential()
        - network3.add_module('flat', nn.Flatten(start_dim=1))
        - network3.add_module('hidden', nn.Linear(in_features, out_features))
        - network3.add_module('output', nn.Linear(out_features, out_classes))

### Creating data
    a1 = torch.Tensor(data)
    a2 = torch.tensor(data)
    a3 = torch.as_tensor(data)  # SHARE
    a4 = torch.from_numpy(data) # SHARE

    - use `torch.tensor()` for normal work
    - for tuning / performance use: `torch.as_tensor()` 
        - (can accept any array-like Python data structure,
          rather than JUST numpy arrays)
    - Keep in mind about memory sharing:
        - Since `numpy.ndarray` objects are allocated on the CPU,
          the `as_tensor()` function must copy the data from the
          CPU to the GPU when a GPU is being used.
        - The memory sharing of `as_tensor()` doesn't work with
          built-in Python data structures like LISTS.
        - The `as_tensor()` call requires developer knowledge of
          the sharing feature. This is necessary so we don't
          inadvertently make an unwanted change in the underlying
          data without realizing the change impacts multiple
          objects.
        - The `as_tensor()` performance improvement will be
          greater if there are a lot of back and forth operations
          between numpy.ndarray objects and tensor objects.
          However, if there is just a single load operation,
          there shouldn't be much impact from a performance
          perspective.


### terminology
    - "modules": 
        - in Pytorch, we often think of 'layers' inside a network
          as 'modules', and even networks as 'modules' too (if we
          are composing networks together using nn.Sequential)
            - for module in network.childre():
            -   # 'module' here is actually each 'layer' in the
            -   network (conv layer, dense layer etc)
            -   module.reset_parameters()
        - aside: 
            - but 'Softmax' could appear as a "module" in
              netowrk.children() and u can't call
              `reset_parameters()` on a Softmax module/layer.
        - solution:
            - save snapshots

    - layer or operation?
        - "layers": 
            - any operation defied using 'weights' 
        - "operations": 
            - any operations that don't have weights involved:
            - `relu` activation is an operation
            - max `pooling` is an operation
                - ...they're called from `nn.Functional`
            - Bad terminology: 
                - Sometimes pooling operations are called
                  "pooling layers"... and even activation
                  operations called "activation layers". 
        - Mathematically: a NN is a composition of functions, and
          is a function itself.

    - Indexes  CS         MATHS
    - -------  --         -----
    - 0        number     scalar
    - 1        array      vector
    - 2        2d-array   matrix
    - n        nd-array   (nd-)tensor

    - rank:
        - rank: tells us how many _indices_ we need to refer to
          a specific element in the data structure.
        - a rank-2 tensor means all of these:
            - a matrix
            - a 2d-array
            - a 2d-tensor
    - axis:
        - An axis of a tensor is a SPECIFIC DIMENSION of
          a tensor. 
    - shape: 
        - tells us how many INDICES are AVAILABLE along each axis
        - note: the `size` of a tensor is the same as the `shape`
          of a tensor in pytorch
        - so now we have another way of knowing the `rank`: it's
          the length of its `shape`
        - shape is useful: 
            - the length (number of elements) in `shape` actually
              gives us the rank of the tensor (i.e. the number of
              different dimensions)
        - shape changes the grouping of the data elements, but
          doesn't change the underlying data itself

    - feature maps
        - With the output channels, we no longer have color
          channels, but modified channels that we call feature
          maps. These so-called feature maps are the outputs of
          the convolutions that take place using the input color
          channels and the convolutional filters. 

    - element-wise
        - same as 'component-wise', 'point-wise'

### Handy seeding code

    def seed_everything(seed_value):
        random.seed(seed_value)
        np.random.seed(seed_value)
        torch.manual_seed(seed_value)
        os.environ['PYTHONHASHSEED'] = str(seed_value)
        if torch.cuda.is_available():
            torch.cuda.manual_seed(seed_value)
            torch.cuda.manual_seed_all(seed_value)
            torch.backends.cudnn.deterministic = True
            torch.backends.cudnn.benchmark = True

    seed = 42
    seed_everything(seed)
