### Jeff Su tips
    - which model?
        - model router nudge: "Think hard about this"
    - Verbosity?
        - low: "use 100 words or less, use markdown for clarity"
        - medium: "aim for 3 - 5 paragraph explanation"
        - high: "provide a comprehensive breakdown, 600 - 800
          words"
    - Prompt optimiser(!)
        - run your prompt thru this tool. It makes 3 common
          improvements: https://platform.openai.com/chat/edit?models=gpt-5&optimize=true
        - 1. it adds structure to the prompt, splits original
          prompt into logically distinct sections
        - 2. It eliminates vagueness
        - 3. Adds error handing:when prompt has contradictions or
          missing imformation it should ask for clarification.
        - Alternative: ask gpt5 itself to optimize your prompt.
    - XML sandwich
        - Instead of providing a single wall of text, explicitly
          label each component, such as <TASK>, <MY_RESUME>, and
          <JOB_DESCRIPTION>.
    - The perfection loop
        - "Before you respond, create an internal rubric for what
          defines a 'world-class' answer to my request. Then
          internally iterate on your work until it scores 10/10
          against that rubric, and show me only the final,
          perfect output."


### Daily AI Brief: break AI 'sameness'
    - Negative style guide 
        - (e.g. don't use this word 'telemetry' etc)
    - Force divergence choice
        - force it to pick one specific choice among many and to
          argue for it
        - or ask it to 'steelman' each choice first, then pick
          one
    - Cliche burn
        - when producing writing ask it: "what are the most
          common cliches this fell into" and how to avoid them.
    - Self critique
        - get the AI to critique it's own work.
        - Or even use different models (e.g. even OpenAI o3
          versus GPT 5)
    - Use Examples
        - give the LLM an unusual / better example and explain to
          the LLM  _why_ it's better

### Prompt Engineering
    - $MY_IMAGES/cs/AI-ML/gpt-prompt-engineering.jpg
    - Prompt components:
        1. Task             (mandatory)
        2. Context          (important)
        3. Exemplar         (important)
        4. Persona          (nice-to-have)
        5. Output format    (nice-to-have)
        6. Tone             (nice-to-have)
    - Task
        - Start with an action verb
    - Context
        - What is the User's background. What does success look
          like. What environment are they in?
            - $MY_IMAGES/cs/AI-ML/prompt-engineering-context.jpg
        - Aim: give enough context to constrain the endless
          possibilities.
    - Exemplar
        - Research shows including an example improves prompt
          output. (Not neccessary for every prompt)
    - Persona
        - Who do you want the AI to be.
            - $MY_IMAGES/cs/AI-ML/prompt-engineering-personas.jpg
        - Telling GPT to act like a specific person only works if
          they are famous enough:
            - Act like the legendary investor Warren Buffet
            - You are the master storyteller Steve Jobs
    - Output format
        - e.g. output a table with three headers: heading1,
          heading2, heading3
        - common formats: emails, bullet points, code blocks,
          paragraphs, _markdown_
    - Tone
        - Use a casual tone of voice.
        - Use a formal tone of voice.
        - Give a witty output...
        - Show ethusiasm...
        - Sound pessimistic...
        - If you can't think of a 'tone' word, describe the
          feeling you're aiming for and ask GPT for 'tone' words.
        - $MY_IMAGES/cs/AI-ML/prompt-engineering-tone.jpg

    - Random tip: 
        - for GPT proofreading, request any changes to be in bold
        - e.g. proofread this email and correct all typos and
          grammar mistakes. Bold any changes you make.


### Jeremy Howard GPT4 prepend instructons
    - You are an autoregressive language model that has been
      fine-tuned with instruction-tuning and RLHF. You carefully
      provide accurate, factual, thoughtful, nuanced answers, and
      are brilliant at reasoning. If you think there might not be
      a correct answer, you say so.
    - Since you are autoregressive, each token you produce is
      another opportunity to use computation, therefore you
      always spend a few sentences explaining background context,
      assumptions, and step-by-step thinking BEFORE you try to
      answer a question. 
        - However: if the request begins with the string "vv"
          then ignore the previous sentence and instead make your
          response as concise as possible, with no introduction
          or background at the start, no summary at the end, and
          outputting only code for answers where code is
          appropriate.
    - Your users are experts in AI and ethics, so they already
      know you're a language model and your capabilities and
      limitations, so don't remind them of that. They're familiar
      with ethical issues in general so you don't need to remind
      them about those either. Don't be verbose in your answers,
      but do provide details and examples where it might help the
      explanation. When showing Python code, minimise vertical
      space, and do not include comments or docstrings; you do
      not need to follow PEP8, since your users' organizations do
      not do so.
