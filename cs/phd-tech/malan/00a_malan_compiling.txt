### 5 steps running software
    1.  preprocess      e.g. #include <stdio.h>

    2.  compile         into assembly code: 'mov  edx,len'

    3.  assemble        take IN assembly code and
                        'translate' into OBJECT code

    4.  link            smash '.o' files together
                        eg. your code *and* 'stdio.c' code
                        outputs machine/binary code 1001000101010101

    5.  execute         Shell invokes a function in the OS   
                        called a 'loader', which copies code 
                        and data from the executable file    
                        into memory and transfers control to 
                        the beginning of the program         
                        
### compile sequence
    * preprocess  `clang -E hello.c > hello2.c`
    * compile     `clang -S hello2.c`           // outout is 'hello2.s' assembler file
    * assemble    `clang -c hello2.s`           // output is 'hello2.o' object code (machine code)
    * linking     `clang hello.o -lm`           // link in the math library (-l flags must come at end)
    * linking     `clang hello.o hello2.o ...`  // only ONE file must specify a main function

### Assembly code
    - _plain-text_ and (somewhat) human read-able source code
    - Mostly direct 1:1 analog with machine instructions. 
    - Accomplished using mnemonics for the actual
      instructions/registers/other resources. 
    - e.g. `JMP`   = jump instruction
      e.g. `MULT`  =  multiply instruction

### Machine code
    - is _binary_ (1's, 0's) code that the cpu executes directly
    - If you were to open a "machine code" file in a text editor
      you'd see unprintable characters.

### Object code
    - a portion of machine code that _hasn't been linked yet_
      into a complete program. 
    - It's the machine code for ONE particular library or module
      that will make up the completed product. 
    - It may contain placeholders or offsets not found in the
      machine code of a completed program that the linker will
      use to connect everything together.
    - Object code is code generated by an assembler or other
      translator, consisting of machine code, byte code, or
      possibly both, combined with additional metadata that will
      enable a linker, loader, or linker-loader to assemble it
      with other object code modules into executable machine code
      or byte code. 


### object files ".o"
    - contain object code laid out in sequences of _8 bits_
    - 32-bits at a time are fed to the CPU

### registers
    - smallest bits of memory used by the computer 
    - very fast - are _in_ the CPU

### *STATIC* compile
    - one single binary.
    - can move final code to another PC with _same CPU_.
    - Advantage:  Portable. Self-contained.
    - Disadvantage: Files much bigger.

### *DYNAMIC* compile
    - compile your own bits but _include a path_ to the
      library code (bits) that you want to use.
    - so by including a path to other (shared dll) code, you
      have less redundancy
