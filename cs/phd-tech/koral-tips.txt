### David info
    - I had a thought about what to do about the inner boundary.
      If you remember, the way it works is we have two ghost
      cells indexed by `i=-2` and `i=-1`.
    - We then take information from cell `i=0` to set explicitly
      the fluid quantities in both ghost cells.

    - What we want for our boundary condition is to prevent any
      gas from entering the domain.
    - Gas enters the domain through the cell boundary based off
      of the mass flux at the boundary. The mass flux at any cell
      boundary `i+1/2` (think between `i` and `i+1`) is
      calculated by taking information from cell `i-1`, cell `i`,
      cell `i+1`, and cell `i+2` to produce two fluxes at cell
      boundary `i+1/2` and then those fluxes are essentially
      averaged to compute the final flux.
    - It's a little more complicated than a straight average but
      for a first approximation we can just think of it as an
      average. Then to get zero mass flux we are going to want to
      have these two fluxes add to zero. The way to do this is to
      copy the density and pressure from cell 0 to cell -1, and
      from cell `1` to cell `-2`.
    - We then copy the velocity in the same way except we
      multiply the radial component by -1.

### David Info
    - fill_geometry_arb
        - is declared in metric.c. As you can see from the
          comment it fills the metric struct with a metric of
          your choosing, in our case we need to add
          Reissner-Nordstrom.
        - It's used in init.c because we need to use some metric
          quantities to calculate the initial condition for
          whatever problem you found it in.

    - coco_N
        - declared in metric.c is useful if we ever want to
          change coordinates. In our case, we define the metric
          in spherical coordinates, and at the moment we can
          stick to those so I'm not sure if we'll need to call
          coco_N, but if we do the transformation should be
          trivial.
        - If we want to change to a coordinate system (but with
          the same metric) with non-uniform spacing in `r` for
          example, then we'll need to do something more
          complicated here.

    - trans2_coco
        - transforms a vector quantity. It's declared in frames.c
          for some reason but it usually relies on routines from
          metric.c.
        - Again, if we're using spherical coordinates for the
          whole calculation, then I'm not sure if it's going to
          be necessary to include the transformation here but we
          can add one just in case.

    - tools.c
        - is a problem dependent file where you write some
          problem dependent tools.
        - In our case, we won't be doing a disk simulation so
          probably we won't need to use any of those tools for
          disk problems.

    - Hope that all makes sense! Try to remind yourself the
      difference between changing coordinates, changing frames,
      and changing metrics.
