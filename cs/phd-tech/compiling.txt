

### mcmodel
    - Tells the compiler to use a specific memory model to
      generate code and store data.
    - If your program has COMMON blocks and local data with
      a total size smaller than 2GB, -mcmodel=small is
      sufficient. COMMONs larger than 2GB require -mcmodel=medium
      or -mcmodel=large

    - `small`: Tells compiler to restrict code and data to the
      2GB of address space. All accesses of code and data can be
      done with Instruction Pointer (IP)-relative addressing.

    - `medium` Tells compiler to restrict code to first 2GB; it
      places no memory restriction on data. Accesses of code can
      be done with IP-relative addressing, but accesses of data
      must be done with absolute addressing.

    - `large` Places no memory restriction on code or data. All
      accesses of code and data must be done with absolute
      addressing


### System dynamic linker configuration
    - aka "Shared libraries"
    - Config in: 
        - /etc/ld.so.conf
    - Contains:
        - `/etc/ld.so.conf.d/*.conf`

### compile no optimisation
    - method 1
        - Starting with gcc 4.8 the optimization level `-Og` is
          available. It enables optimizations that do not
          interfere with debugging and is the recommended default
          for the standard edit-compile-debug cycle
    - method 2
        gcc -Q --help=optimizers test.c | grep enabled
        - disable as many as you like with:
        gcc **-fno-web** -Q --help=optimizers test.c | grep enabled
        - info - https://gcc.gnu.org/onlinedocs/gcc/Optimize-Options.html

### Preprocessor is important
    - Important use case: Some external library you need changes
      function signature and you need the ability to compile
      against the old or new library, eg:
            - #if LIBVERSION >= 2
            -   draw_point (2, 3, RED);
            - #else
            -   set_color (RED);
            -   draw_point (2, 3);
            - #endif

    - The preprocessor is still needed to implement a routine
      that allocates memory on the stack in a cross-platform way.

### Linking Summary
    - The linking technique allowing programs to be constructed
      from multiple object ".o" files.
    - Linking can happen at different times in a programs
      lifetime:
        - Compile time 
        - Load time   ("execve")
        - Run time    (while a program is executing!)

### gcc args "-l"
    - gcc -L. libtest.o -lmine
    - here `-lmine` is shorthand for `-L mine.a`
        - ie the "mine.a" archive

### Avoid funny Linker errors
    - Global Variables
       - Avoid if you can
    - Otherwise
       - Use STATIC if you can
       - Initialize if you define a global variable (help the
         linker catch errors, you might have two strong
         initialised global variables so the Linker will tell you
         there's a problem)
       - Use EXTERN if you reference an external global variable

### compilation commands
    - `-E`: dump code after preprocessing
        - $ clang -E example.c

    - `-D`: define macro
        - $ gcc -DCONDITION -E main.c
        - good feature. Allows macros to be defined out of source
          files. Helpful if single code but compiling for
          different architectures.
