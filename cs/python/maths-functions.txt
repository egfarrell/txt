### Integer Division
    If BOTH operands are integers then "a/b" results in the (truncated)
    integer "c", such that bc =< a

    So (x=5/9) results in (x=1) which can cause a fair surprise down the
    line. Normally integer division should be avoided but it can be
    deliberately forced with a double slash "//"

### Float Division
    Integer division can be turned off by a Python switch but better to
    force one of the operands to be a float object e.g. (9.0/5) or (9/5.0)
    or (float(9)/5)

### Round off Errors
    Real numbers (Floats) are normally only stored up to 16 digits. The rest of the digits are truncated.
    `(1/49)*49 returns 0.9999999999999999`
    `(1/51)*51 returns 1.0000000000000000`

    This is because of how (1/49) and (1/51) are stored internally.

    Python has a special "decimal" module which allows real numbers to be
    represented with adjustable accuracy.
