### S-Expressions
    - Actually what we did above was theoretically bad. We
      defined a function in one S-expression and used it in
      another S-expression. Two separate S-expressions.
    - The first S-expression had an effect, it left a definition.
      You dont want that in Lisp. 
    - In theoretical Lisp, an expression has to define within
      itself all the functions it needs, and then use them.
      Because theres no lasting effect of evaluating a Lisp
      expression.
    - Think about this: The only way to get a value assigned to
      a variable is to have it be the argument of a function
      which binds the value to the variable within the
      appropriate scope. (???)  
    - The correct one-expression version of factorial uses
      'let-be-in', which is a 3 argument function:  
      - ```
      - let (fact N) if = N 1 1 * N (fact - N 1)
      - (fact 3)
      - ```
    - This expands to:
        -   ```
        -   ('lambda (fact) (fact 3)
        -    'lambda (N) if = N 1 1 * N (fact - N 1)
        -   )
        -   ```
        - Note 1: function definitions are triples of 
        - `(lambda (arguments) body)`
        - Note 2: ' is the one-qrgument quote function, meaning
          no evaluation occurs
