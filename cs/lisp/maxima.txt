### iPhone Recordings: Dec 26, 2020
    - COMPLEX NUMBERS
        - Maxima calculations are performed over the entire field
          of complex numbers. This makes the results completely
          general.
        - But it sometimes prevents the computation of an
          integral, or the solution of an equation, when no
          totally general solution exists
    - ASSIGNMENTS V EQUATIONS
        - remember the difference between an assignment and an
          equation. 
        - an assignment stores a value in a variable e.g. `a : 1`
        - an equation is simply the statement that `a = 1`. An
          equation will not _change_ the actual value of `a`
    - VARIABLE NAMES 
        - if you want a variable name like `b+` or `a-`, then
          escape the `+, -` with a backslash (Senese, p. 136)
    - INTERPOLATION 
        - p. 145 boodling function from interpolated data: trick
          with DOUBLE QUOTE
    - FUNCTIONAL DEPENDENCY 
        - p. 164 
        - it's best to show the dependence of a function `f` on
          variables `x, y` by typing it out explicitly `f(x, y)`
          rather than using the Maxima `depends` function to
          declare dependancies
            - gotcha: you can use `depends` for derivatives, but
              not for integrals, or integral transforms
    - PLOTTING 
        - to plot the critical points on a surface, you have to
          use the `Draw3D` environment, rather than the much
          simpler `plot3D` that's covered in the Senese book

### Jargon
    - ATOM
        - names of variables or procedures,
        - numbers (integer or floating-point),
        - "strings" (enclosed in double-quotes).

    - LIST
        - Ordered set of objects, written as a comma-separated
          list of items in square brackets: eg: [a, b, c]

    - NOUN
        - A literal, symbolic name, that isn't evaluated.
        - operator:    myfunc
        - NOUN form:  'myfunc (not evaluated)
        - VERB form: ''myfunc (force evaluation)
        - as opposed to:

    - VERB
        - the execution of a procedure, or value of a variable, 
          invoked by using its name.
          (See the discussion of evaluation below.)

    - PREDICATE
        - LISP: "predicate" is a function that tests a condition.
          By convention, LISP predicate names end in "p".
        - You'll notice a lot of these in maxima. They return
          Boolean true or false.

    - EVALUATION
        - Often see: “This function evaluates its arguments”
            - Actually, most maxima functions evaluate their
              arguments; but a few dont.
        - Sometimes it's necessary to change the default
          behavior, and either inhibit or force evaluation.
        - Use _single quote_ operator
            - myfunc
            - NOUN form:  'myfunc (not evaluated)
            - VERB form: ''myfunc (force evaluation)

        - handy hint: single-quote operators protect the name
          that follows from evaluation, much like single quotes
          protect arguments from expansion in UNIX.

### MAXIMA init Files
    - ~/.maxima/maxima-init.mac

    - Older info?
    - Several initialization files, if in place, are loaded into
      every maxima when you enter maxima top-level the first time
      by typing (run).
    - CL file: /usr/local/maxima/obj/maximarc.lsp is loaded into
      every maxima. Therefore it is the place we put fixes for
      MAXIMA bugs.

    - For each individual user, the file .maxima.lsp in the home
      directory is a private init file which will be loaded after
      loading maximarc.lsp. For example, one may have the
      following lines in one's .maxima.lsp file.
    ```
    (loadfile "file1.lsp")
    (loadfile "file2.lsp")
    (setq $fpprec 30)
    ```

    - The effect of this file (when loaded automatically into
      maxima) is to cause loading of the two indicated CL files
      and the setting of the variable $fpprec to 30.

    - After loading the above two initialization files, maxima
      looks for a file under the name .maxima-wd.lsp in the
      current working directory. If found it is also loaded. This
      allows different initialization to be done if the maxima
      system is invoked in different working directories. Thus,
      for example, one may have a finite-element .maxima-wd.lsp
      in one directory and a factoring .maxima-wd.lsp in another
      directory. This makes working with MAXIMA under different
      testing conditions much easier.

### Code example
    - The Maxima solution can be simplified quite a bit..
    - There is no need for (arcane) functions like funmake or
      matrixmap.
    - There is also a standard function for identity matrices
      (`ident(2)` for a 2×2 one). And I prefer curly brackets for
      control blocks.
    - Then we get:
        for a:0 thru 4 do
        for b:0 thru 4 do
        for c:0 thru 4 do
        for d:0 thru 4 do
        {
            M: matrix([2,0],[0,3]),
            P: matrix([a,b],[c,d]),
            if mod(transpose(P).M.P, 5) = ident(2)
            then print(P)
        };
