### object
    - a dynamic collection of properties
    - (not an instance of a class as in other languages!)
    - every property has a key string which is unique within that object.
    - javascript doesnt use classes, it uses prototypes
    - prototypes is an easier program model, don't have to "classify" a whole system
    - just do object.create and pass some object to inherit.(used to have "new" operator)
    - "prototypes" is sometimes call "delegation" or "differential inheritance"

### Property
    - named collection of attributes
    - name,
    - 3 boolean flags: writeable, readable, enumerable
    - get: add function which will be called in any attempt to get from object
    - set: add function which will be called in any attempt to set from object

### two kinds of property

# edge case problems in ES3
    - accidental collisions: if you pass in the word "constructor" to a word count function
    - you will get truthy back instead of a number!!! cos word_count["constructor"] already exists.
    - solution: if typeof word_count[word] = 'number' ...

    - funcions inherited from the prototype are included in for in enumeration
    - using "for in" you start to cycle through some of the inherited methods
    - if object.hasownproperty(name) will fill if prototype has "hasownproperty"
    - solution: if object.prototype.hasownproperty.call(object, name)

### edge case solutions in ES5
    - object.createe(null) doesnt inherit anything
    - set enumerable to false when adding methods to prototypes
    - object.keys(object) produces keys of own properties, not inherited ones

### "truthy"
    - if you put it in the control part of an `if` statement it
      will take the `then` branch
    - "0"     is truthy cos not empty string
    - "false" is truthy cos not empty string

### "falsy"
    if you put it in the control part of
    an if statement it will take the else branch
    false, null, undefined, 0, NaN, == empty string

### objects
    - can be passed to functions and returned by functions
    - are passed by reference, not by value.
    - So objects never really copied.
    - equality `===` compares object _references_, not values.
    - therefore `true` if both are same object.

### functions
    - are key idea.
    - Other languages have methods, class, constructor, module
    - they inherit from function.prototype.
    - so functions have methods!!
    - "hoisting": if you declare a var and give it a value,
    the declaration gets hoisted to the top, and the value assignment
    stays where it is.
    - this means there is no BLOCK SCOPE (ie inside curly braces),
    - only FUNCTION scope
    - can have function statements and function expressions.
    - which is which?
    - if the first word is "function" then its a function statement.
