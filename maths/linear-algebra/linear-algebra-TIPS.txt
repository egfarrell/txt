### "Homogeneity"
    - Linear transformations preserve:
        - Property 1. Vector addition
        - Property 2. Homogeneity
            - (Preserves Scalar Multiplication)
            - `L(c * v) = c * L(v)`
    - Why "homogeneity"?
        - From the Greek `homos`, meaning "same."
            - It signifies the output of transformations behave
              the 'same way' wrt scalar multiplication.
            - ie, maintains the SAME proportionality: 
                - if the input is scaled by a factor of `c`, the
                  output is also scaled by `c`.
        - Connection to Homogeneous Functions
            - In general, a function `f(x)` is called homogeneous
              of degree `k` if scaling its input by `c` results
              in scaling the output by `c^k`, i.e.,
                - `f(cx)=c^k ∙ f(x)`
            - For linear transformations, `k=1`, meaning they are
              homogeneous of degree 1. This special case means
              the transformation preserves _linear scaling_
              exactly.
    - Why "homogeneity" 2:
        - Because it reflects how scaling a vector scales the
          output in the SAME WAY—preserving the "uniformity" of
          scaling.
        - Etymology:
            - From Greek homogenēs:
                - homos = same
                - genos = kind or type
                - → "Of the same kind"
        - Why it applies in linearity:
            - Here 'homogeneity' means that applying a scalar to
              the input and then the transformation gives the
              same kind of result as applying the transformation
              first and scaling later:
            - L(c * v) = c * L(v)
            - This ensures the output _behaves uniformly_ with
              respect to scalar multiplication.
        - In short: "homogeneous" implies uniform scaling
          behavior, which is central to linear structure.

### Matrix multiplication
    - First saw it in high school, where matrices are presented
      without any real motivation, and matrix multiplication
      seemed a weirdly-defined operation.
    - When I did linear algebra in college and matrix
      multiplication was presented as the way to _compose linear
      transformations_, it made way more sense.
    - reply
        - The easiest way to describe matrix multiplication is
          nested function composition.
            - f(x) = 2x
            - g(x) = x + 5
        - It should hopefully be obvious that "nesting" the two
          isn't commutative:
            - g(f(x)) = (2x) + 5 = 2x + 5
            - f(g(x)) = 2(x + 5) = 2x + 10
        - A miraculous fact is that no matter how many functions
          we stack, we only ever have two terms: `x` and
          a constant term.
        - Thus, we can represent this 'linear system' in terms of
          its coefficients, as long as we agree on an order:
            - e.g. `2x + 5` might become "`2, 5`" in our system.
        - You can do "multiplication" on these packs to compose
          them together, and even though the rules feel obtuse,
          they follow the logic of FUNCTION COMPOSITION.
        - A matrix represents a similar function transform, only
          in 3 dimensions, and in order to handle rotation, it
          needs to swap around x/y/z.
        - So an `identity matrix` is really saying:
            - f(x) = 1x + 0y + 0z + 0
            - f(y) = 0x + 1y + 0z + 0
            - f(z) = 0x + 0y + 1z + 0
        - reply
            - Aced my university linear algebra class with no
              idea what I learned. It didn't start to click until
              I started using it for tangible problems.
        - reply
            - Matrices are funny. You encounter them as

### Interesting: Limited Vocabulary of Linear Algebra
    - Use GA for software...
    - $MY_BOOKS/Physics/Maths/Algebra/Efficient-Implementation-of-Geometric-Algebra-Fontijne.pdf
    - The problem with linear algebra is that its vocabulary is
      limited, leading to all kinds of kludges.
    - Some examples:
        - Vectors formalize DIRECTIONS, but in geometry one often
          needs POINTS. This is solved by introducing an
          ‘origin’, relative to which vectors can indicate
          points.
        - One problem with this idea is the semantic difference
          between a `DIRECTION VECTOR` and a `POINT VECTOR` is
          not encoded in the vector type itself.
    - In software, both concepts are represented by the same
      vector type, and interpretation is up to the coder.
        - Eg, the coder must remember that sometimes
          point-vectors TRANSFORM differently than
          direction-vectors.
    - Each line of the singular column can be made quantitative
      using `r`.
